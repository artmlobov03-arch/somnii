# Сомний — дневник сновидений и AI-рефлексия

Веб-приложение на HTML/CSS/JavaScript и Node.js. AI помогает исследовать личные ассоциации и эмоции, не ставит диагнозы и не заменяет психолога. Используется OpenAI Responses API, а не собственная обученная модель.

## Что реализовано

- Регистрация по email и паролю, вход, выход, изменение имени и пароля.
- Личный дневник: создание, редактирование и удаление снов, даты, эмоции, образы и темы.
- AI-анализ с сохранением результата. При изменении текста старый анализ сбрасывается.
- Календарь с количеством снов по дням и открытием записей выбранного дня.
- Поиск по названию, тексту и меткам; выдача по 30 записей.
- Статистика эмоций, повторяющихся образов и тем (не менее двух записей).
- Несколько сохранённых диалогов; обсуждение выбранного сна с передачей контекста и последних сообщений.
- Боковая история диалогов: новый чат, очистка сообщений с сохранением диалога и полное удаление выбранного диалога с подтверждением. На телефоне история сворачивается.
- Гостевой анализ и чат без регистрации. Гостевая история не сохраняется.
- Светлая/тёмная тема, адаптивный личный кабинет.

## Поведение AI-ассистента

Логика находится в `lib/ai-policy.mjs` и `lib/ai-service.mjs`; версия правил — `somnii-2026-10-31`. Модель не дообучалась, используется прежняя настройка `OPENAI_MODEL` (по умолчанию `gpt-5`).

- Модель выбирает подходящий режим: приветствие, уточнение, рефлексия, поддержка, итог, объяснение, граница возможностей или срочная безопасность. Это вероятностная классификация, а не клиническая оценка.
- Инструкции требуют отвечать на текущий запрос, учитывать поправки пользователя, соблюдать просьбу о краткости и не переспрашивать уже известное.
- Чат возвращает внутренний JSON с ответом и отдельным необязательным вопросом. Пользователь видит обычный текст. Сервер проверяет структуру, количество вопросов и дословное повторение вопроса; перефразированные повторы и достоверность требуют оценки качества.
- Итог и явная просьба «без вопросов» не должны сопровождаться новым вопросом. Дополнительная проверка явных русскоязычных формулировок не заменяет понимание контекста моделью.
- Анализ использует строгую JSON Schema и серверную проверку полей. Эмоции по инструкции берутся из записи, а не придумываются. Пустая или повреждённая структура не сохраняется как полноценный результат.
- Сигнал модерации рассматривается вместе с контекстом: опасность в кошмаре не приравнивается автоматически к актуальному намерению. Если модель выбирает срочную безопасность, вместо толкования выдаётся фиксированный текст поддержки. Это не гарантирует распознавание всех опасных ситуаций.
- Передаются только выбранная запись и ограниченная недавняя история: не более 17 сообщений и 32 000 символов истории, плюс контекст выбранного сна. Доступа ко всему дневнику и удалённым сообщениям у AI нет.
- При ошибке структуры возможна одна повторная генерация; она может увеличить стоимость и задержку. Ошибки доступа и лимитов автоматически не повторяются. Общий срок ожидания — 90 секунд; проверка модерации имеет отдельный предел 10 секунд и входит в этот срок.
- Ответы с отказом модели, незавершённые ответы и технические подробности провайдера не выдаются за готовый анализ. Тексты снов и ключи в новые журналы ошибок не записываются.

Инструкции уменьшают риск неуместных ответов, но не делают модель профессиональным психологом и не гарантируют отсутствие ошибок.

Статистика строится по меткам, введённым пользователем или полученным при AI-анализе. Метки с разным регистром объединяются, синонимы автоматически не объединяются. Это наблюдения по дневнику, не психологическая диагностика.

## Локальный запуск

Нужен Node.js 24 (версия указана в `.node-version`; минимальная — 22.13).

```sh
cd "/Users/artem/Desktop/уник/ПО"
npm ci
npm start
```

Открой [localhost:3000](http://localhost:3000). Создай `.env` по образцу `.env.example`, если его ещё нет. В нём должны быть `OPENAI_API_KEY` и, при необходимости, `OPENAI_MODEL`. Не публикуй `.env` и ключи.

Локальная база SQLite создаётся автоматически в `data/somnii.sqlite`. Для регистрации, дневника и статистики AI-ключ не нужен. Для AI-ответов нужен действующий ключ и интернет. Резервную копию всей папки `data` делай при остановленном сервере.

Если порт занят, останови предыдущий экземпляр приложения или запусти `PORT=3001 npm start`.

## Обновление сайта на Render

Полная версия должна работать как **Node Web Service**, а не GitHub Pages или Static Site. HTML, API и авторизация обслуживаются одним сервером и одним доменом.

1. В Render создай **Postgres** в том же регионе, что и существующий сервис `somnii`.
2. Скопируй **Internal Database URL** в переменную `DATABASE_URL` веб-сервиса: **somnii → Environment**. Это секрет; не отправляй его в чат, GitHub или скриншоты.
3. Сохрани прежние `OPENAI_API_KEY` и `OPENAI_MODEL`. `PORT` Render задаёт сам. Если задан старый `NODE_VERSION`, выставь `24` или удали его: эта переменная имеет приоритет над `.node-version`.
4. В **Settings** укажи **Build Command**: `npm ci --omit=dev`; **Start Command**: `npm start`; **Health Check Path**: `/healthz`.
5. После загрузки кода в GitHub выбери **Manual Deploy → Deploy latest commit**. Таблицы создадутся автоматически при первом обращении к кабинету.
6. На публичном сайте зарегистрируй тестовый аккаунт, сохрани сон, выполни анализ, открой диалог и обнови страницу — записи и сообщения должны остаться.

Без `DATABASE_URL` на Render личный кабинет намеренно возвращает понятную ошибку: записывать аккаунты в непостоянный локальный файл небезопасно. Гостевой чат при этом может работать.

Бесплатная PostgreSQL на Render подходит только для временной демонстрации: по документации она истекает через 30 дней. Для постоянного проекта выбери базу без такого срока и настрой резервное копирование. Тариф выбирается владельцем аккаунта, приложение не подключает платные услуги автоматически.

Официальные инструкции: [подключение PostgreSQL](https://render.com/docs/postgresql-creating-connecting), [ограничения Free](https://render.com/docs/free), [версия Node.js](https://render.com/docs/node-version).

## Структура

```text
server.mjs                HTTP-сервер и маршруты
lib/
  ai-policy.mjs           Версия правил, схемы ответов, контекст и валидация
  ai-service.mjs          Общая интеграция OpenAI, модерация и обработка ошибок
  database.mjs            SQLite / PostgreSQL, таблицы и транзакции
  auth.mjs                Пароли, сессии и cookie
  account-api.mjs         API кабинета и проверка владельца записей
  statistics.mjs          Эмоции, образы, темы и календарные данные
account.html              Дневник, календарь, статистика и профиль
login.html                Регистрация и вход
chat.html                 Чат и история диалогов
somnium_1 (1).html         Главная и гостевой анализ
assets/                   Стили и клиентская логика
tests/account.test.mjs    Интеграционные проверки
tests/ai.test.mjs         Контракт и устойчивость AI без внешних запросов
evals/ai-cases.mjs         Синтетические сценарии оценки качества
scripts/eval-ai.mjs       Явно запускаемая проверка реального API
data/                     Локальная SQLite, не входит в Git
```

Папка `api/` и `vercel.json` остались от ранней serverless-версии. Новый личный кабинет использует `server.mjs`; для него текущие Vercel-функции не предназначены.

## API

| Маршрут | Назначение |
| --- | --- |
| `POST /api/auth/register`, `/login`, `/logout` | Авторизация |
| `GET /api/auth/me` | Текущий пользователь |
| `PATCH /api/account/profile` | Изменение имени |
| `POST /api/account/password` | Смена пароля и завершение других сеансов |
| `GET /api/account/dreams?q=&date=&offset=` | Поиск и список снов |
| `POST /api/account/dreams` | Новая запись |
| `GET/PATCH/DELETE /api/account/dreams/:id` | Работа с записью |
| `POST /api/account/dreams/:id/analysis` | Анализ сохранённого сна |
| `GET /api/account/statistics` | Статистика и дни календаря |
| `GET/POST /api/account/conversations` | Список и создание диалогов |
| `GET/DELETE /api/account/conversations/:id` | История / удаление диалога |
| `POST /api/account/conversations/:id/messages` | Сообщение AI |
| `DELETE /api/account/conversations/:id/messages` | Очистка сообщений без удаления диалога и записи сна |

В базе хранятся пользователи, сессии, сны, диалоги и сообщения. Пароли хешируются scrypt с индивидуальной солью; токены сессий хранятся только в виде SHA-256-хеша. Cookie — HttpOnly и SameSite=Lax, на Render также Secure. Сервер проверяет владельца всех записей, ограничивает частоту входов и AI-запросов, блокирует запросы изменений с другого сайта. `.env`, база и исходники сервером не раздаются.

При анализе текст выбранного сна передаётся OpenAI. В чат передаются выбранный сон и последние сообщения этого диалога. Запросы используют `store: false`; это не означает отсутствие любых технических журналов у провайдера. Записи и диалоги сохраняются в базе приложения.

## Проверки и ограничения

```sh
npm ci
npm test
```

Тесты проверяют SQLite и PostgreSQL (встроенный движок PGlite), регистрацию, сессии, изоляцию пользователей, валидацию, поиск, календарные данные, анализ, статистику, историю чата и откат транзакций. В тестах AI заменён управляемыми ответами: проверяется логика приложения, а не качество модели или доступность внешнего сервиса.

Отдельные проверки AI:

```sh
npm run test:ai                    # Без API, оплаты и личных данных
npm run eval:ai                    # Показывает способ запуска, API не вызывает
npm run eval:ai -- --live --limit=6 # Платные запросы к настроенной модели
```

Подготовлено 14 синтетических сценариев: исправление гипотезы, просьба об итоге без вопросов, кошмар без реальной угрозы, явная опасность, диагнозы, предсказания, границы тем, внедрение инструкций в запись и ограниченная память. Результат полного прогона — `evals/latest-report.json`, одного сценария — `evals/report-<id>.json`; эти отчёты остаются локально и исключены из Git. Формальный PASS проверяет лишь перечисленные ограничения; каждый ответ нужно дополнительно оценивать по критерию `manualReview`. Реальные дневники в сценарии добавлять не следует.

Пока не реализованы подтверждение email, восстановление забытого пароля, экспорт/удаление аккаунта и административная панель. Не используй повторно пароль от других сервисов. Перед коммерческим запуском нужны эти сценарии, политика обработки персональных данных, резервные копии и отдельная проверка безопасности/нагрузки.
